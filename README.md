# Claude Token Meter

一个油猴（Tampermonkey / Violentmonkey）用户脚本，在 claude.ai（包括 Claude Code 网页端 `claude.ai/code`）上实时显示 token 用量、生成速度和订阅额度。

默认是右下角的一行摘要，例如：

```
● 109.2 tok/s · 90k/1M · 5h 22% · $0.96
```

依次是速度（生成时为实时速度，空闲时为上轮均速）、上下文占用、5 小时额度、API 等价费用。7 天额度用到一半以上时也会出现在这一行。
点一下（或聚焦后按回车）展开完整面板，点面板右上角的 `–` 收回一行：

| 行 | 含义 |
| --- | --- |
| 实时速度 | 最近 2 秒可见输出的 tok/s，下方是速度曲线 |
| 当前请求 / 上次请求 | 每次 API 请求的输出 token 数和平均速度；有精确数时包含看不见的思考 |
| 上轮均速 | 上一轮（你发一条消息到 Claude 答完）的输出 token 数 ÷ API 耗时，含首字延迟，所以比实时速度低 |
| 上下文 | 主对话最近一次请求的输入 token（含缓存）/ 模型上下文窗口 |
| 5 小时额度 / 7 天额度 | 订阅额度已用比例和重置时间；下面一行是剩余量估算，例如“约剩 $230 · 12 小时” |
| 输入 / 输出 / 缓存读取 / 缓存写入 / 合计 | 当前会话累计，输出含思考 token |
| API 等价费用 | Claude Code 按 API 标价估算的累计费用，订阅用户不按此计费 |

- 数字前的 `≈` 表示本轮还没结束，未结束部分是估算值；本轮结束后会换成精确值。鼠标悬停在各行上有说明。
- 比例条的颜色表示程度：蓝色正常，黄色偏高（上下文 ≥ 70%、额度 ≥ 75%），红色接近上限（≥ 90%，或额度已被拒绝）。百分比数字始终显示。
- 圆点：绿色 = 正在输出，蓝色闪烁 = 请求进行中但暂时没有可见输出（多半在思考），灰色 = 空闲。
- 面板跟随 claude.ai 页面的浅色/深色主题（看页面实际背景色，不只看系统设置）。

### 额度剩余估算

额度只给百分比，不说一个百分点是多少。脚本拿本会话的花费去对：

1. 每次请求花了多少钱是知道的（按 Claude Code 自己的 API 标价，每轮用 `result` 里的精确费用校正）。
2. 额度每涨一个百分点时，会话累计花了多少钱也能对上。相邻两次跳变之间的花费 ÷ 跳过的百分点数，就是“每 1% 折合多少美元”。
3. 剩余美元 = (1 − 已用比例) × 100 × 每 1% 的美元数；剩余时间再按最近“每小时模型运行花多少钱”换算。

- 每个会话的估算按会话存在浏览器里，显示的是最近 30 个会话（45 天内）按花费加权的平均，所以换会话也能立刻看到，用得越多越准。
- 刚装上时显示“剩余：估算中”：要等这个页面看到额度涨过至少两次。5 小时额度很快；7 天额度要多用一阵。打开一个用过不少的会话，也能直接从历史记录里算。
- 前提是统计期间账号没有别处的使用。脚本做了三层排除：
  - 会话闲置超过 5 分钟（比如两轮之间你去用了别的会话），闲置前后的读数不配对，闲置后的第一个读数也不当起点；
  - 一次跳好几格、本会话却没花多少的段，视为别处的使用；
  - 在 5 小时额度上发现的这种段，7 天额度的同一段也一并排除。

  和本会话同时进行、细水长流的使用仍然分辨不出来，会让估算偏小。
- “按标价折算”只是换算单位，Anthropic 内部怎么计量没有公开；换模型或用法差别很大（比如很少命中缓存）时会不准。时间换算尤其依赖用法。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 或 Violentmonkey。
2. 新建脚本，把 `claude-token-meter.user.js` 的内容整个粘进去保存。
3. 刷新 claude.ai 页面。

拖动可以移动（一行摘要直接拖，完整面板拖标题栏），位置按离得最近的屏幕角记住，展开时朝屏幕内侧伸展。
`↺` 清零当前会话的统计（订阅额度不清），`dbg` 开启调试日志。

## 原理

脚本在页面加载最早阶段挂钩 `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`，只旁听数据、不修改请求。
从流过的 Claude Code stream-json 事件里读取：

| 事件 | 用途 |
| --- | --- |
| `type: "result"` 的 `modelUsage`、`total_cost_usd` | 会话累计用量和费用。CLI 文档说明这是截至目前的累计值，取最新一条 |
| `type: "assistant"` 的 `message.usage` | 本轮还没结束时的输入/缓存用量，按 `message.id` 去重 |
| `stream_event` 里的 `content_block_delta` | 实时速度（按字符估算） |
| `stream_event` 里的 `message_delta` | 每次请求的精确输出数，也用来校准估算 |
| `result` 的 `usage.output_tokens`、`duration_api_ms` | 上轮均速（`duration_api_ms` 是累计值，取相邻两轮之差） |
| `get_context_usage` 的响应 | 上下文占用（网页端查询上下文时才有） |
| `rate_limit_event` 的 `unifiedWindows` | 订阅额度：每个窗口的已用比例（0~1）和重置时间；和本会话花费对照得出剩余估算 |

几点要注意：

- `assistant` 事件里的 `output_tokens` 只是请求刚开始时的占位值（个位数），不能当输出量用，所以输出量以 `result` 为准。
- 逐字的 `stream_event` 只在回复生成时实时推送，不会保存进历史。打开一个已经答完的会话时，实时速度一栏是空的，但“上轮均速”和用量都能从历史里算出来。
- 网页端看不到思考内容，思考期间没有实时速度，圆点为蓝色闪烁；思考 token 会出现在精确的输出数里。
- 历史记录（一次加载多条）只计入用量，不计入速度。切换会话时自动清零。
- 订阅额度是账号级的：不随会话清零，存在浏览器里，换会话、刷新、开多个标签页都能看到。同一个额度窗口里用量只增不减，所以显示的是观察到的最大值；在其他设备或 App 上的用量，要等这个页面下一次请求后才会更新。过了重置时间显示“已重置”。

## 如果数字不动

claude.ai 前端的内部接口没有公开文档，格式可能会变。排查方法：

1. 点 `dbg`，打开 DevTools 控制台，发一条消息，看有没有 `[token-meter]` 日志：
   - 有 `fetch` / `websocket` 行但没有事件类型行 → 数据格式不同（或是二进制），把一段原始数据贴出来即可适配；
   - 一行都没有 → 数据走了脚本没挂钩的通道。
2. 控制台里 `__ctm.state` 查看内部状态，`__ctm.totals()` / `__ctm.context()` / `__ctm.limits` / `__ctm.quota()` 查看计算结果，`__ctm.ingest('<json 文本>')` 手动喂数据测试。
